## 面试点总结

## 总结：
map 是一种key-value的键值对存储结构，其中key不能重复，底层用hash表存储。
Go 语言采用的是哈希查找表，并且使用链表解决哈希冲突。

## 结构：
在go的map实现中，它的底层结构体是hmap，hmap里维护着若干个bucket数组 (即桶数组)，所以维护的是二维数量的桶。
Bucket数组中每个元素都是bmap结构，也即每个bucket（桶）都是bmap结构，每个桶中保存了8个kv对，如果8个满了，又来了一个key落在了这个桶里，会使用overflow连接下一个桶(溢出桶)。这些桶被视为一组，使用链表相接（类似拉链法，但是这里每个结点是一个“桶”，每个桶的里面又可以放8个单位的数据）

## 遍历
每次遍历从随机的地方开始，所以无法保证顺序。
map 遍历的核心在于理解 2 倍扩容时，老 bucket 会分裂到 2 个新 bucket 中去。而遍历操作，会按照新 bucket 的序号顺序进行，碰到老 bucket 未搬迁的情况时，要在老 bucket 中找到将来要搬迁到新 bucket 来的 key。
## 赋值
核心就是类似遍历的双层查找，先找哪个bucket组，然后找具体是哪个bucket的哪个位置。

### 扩容：
如果 map 处在扩容的过程中，那么当 key 定位到了某个 bucket 后，需要确保这个 bucket 对应的老 bucket 完成了迁移过程。即老 bucket 里的 key 都要迁移到新的 bucket 中来（分裂到 2 个新 bucket），才能在新的 bucket 中进行插入或者更新的操作。
上面说的操作是在函数靠前的位置进行的，只有进行完了这个搬迁操作后，我们才能放心地在新 bucket 里定位 key 要安置的地址，再进行之后的操作。

## 删除
计算 key 的哈希，找到落入的 bucket。检查此 map 如果正在扩容的过程中，直接触发一次搬迁操作。

## 关于hash冲突：
当两个不同的 key 落在同一个桶中，就是发生了哈希冲突。冲突的解决手段是采用链表法：在 桶 中，从前往后找到第一个空位进行插入。如果8个kv满了，那么当前桶就会连接到下一个溢出桶（bmap）。
## 扩容：
- 相同容量扩容
  由于map中不断的put和delete key，桶中可能会出现很多断断续续的空位，这些空位会导致连接的bmap溢出桶很长，导致扫描时间变长。这种扩容实际上是一种整理，把后置位的数据整理到前面。这种情况下，元素会发生重排，但不会换桶。

- 2倍容量扩容
  这种2倍扩容是由于当前桶数组确实不够用了，发生这种扩容时，元素会重排，可能会发生桶迁移。
  扩容前B=2,扩容后B=3，假设一元素key的hash值后三位为101，那么由上文的介绍可知，在扩容前，由hash值的后两位来决定几号桶，即 01 所以元素在1号桶。 在扩容发生后，由hash值得后三位来决定几号桶，即101所以元素会迁移到5号桶。

- 发生扩容的条件
  首先我们了解下装载因子(loadFactor)的概念
  loadFactor:=count / (2^B) 即 装载因子 = map中元素的个数 / map中当前桶的个数
  通过计算公式我们可以得知，装载因子是指当前map中，每个桶中的平均元素个数。
  1. **扩容条件1**：装载因子 > 6.5 (源码中定义的)
     这个也非常容易理解，正常情况下，如果没有溢出桶，那么一个桶中最多有8个元素，当平均每个桶中的数据超过了6.5个，那就意味着当前容量要不足了，发生扩容。
  2. **扩容条件2**: 溢出桶的数量过多
     当 B < 15 时，如果overflow的bucket数量超过 2^B。
     当 B >= 15 时，overflow的bucket数量超过 2^15。
     简单来讲，新加入key的hash值后B位都一样，使得个别桶一直在插入新数据，进而导致它的溢出桶链条越来越长。如此一来，当map在操作数据时，扫描速度就会变得很慢。及时的扩容，可以对这些元素进行重排，使元素在桶的位置更平均一些。

- 扩容时的细节
  1. 在我们的hmap结构中有一个oldbuckets，扩容刚发生时，会先将老数据存到这个里面。
  2. 每次对map进行删改操作时，会触发从oldbucket中迁移到bucket的操作【非一次性，分多次】
  3. 在扩容没有完全迁移完成之前，每次get或者put遍历数据时，都会先遍历oldbuckets，然后再遍历buckets。
  4. 每次最多只会搬迁 2 个 bucket。


##  Notes
### 线程不安全

主要考虑扩容时。

在同一时间点，两个 goroutine 对同一个map进行读写操作是不安全的。举个栗子：
某map桶数量为4，即B=2。此时 goroutine1来插入key1， goroutine2来读取 key2. 可能会发生如下过程：
1. ① goroutine2 计算key2的hash值,B=2，并确定桶号为1。 
2. ② goroutine1添加key1，触发扩容条件。 
3. ③ B=B+1=3, buckets数据迁移到oldbuckets。 
4. ④ goroutine2从桶1中遍历，获取数据失败。

### 不可对元素取地址
无法对 map 的 key 或 value 进行取址。以下代码不能通过编译：
```go
fmt.Println(&m["qcrao"])
```
如果通过其他 hack 的方式，例如 unsafe.Pointer 等获取到了 key 或 value 的地址，也不能长期持有，因为一旦发生扩容，key 和 value 的位置就会改变，之前保存的地址也就失效了。

### Float作为key
```go
NaN != NaN
hash(NaN) != hash(NaN)  // (hash函数中对这种情况特殊处理加入了随机值）
```
因此向 map 中查找的 key 为 NAN 时，什么也查不到；如果向其中增加了 4 次 NAN，遍历会得到 4 个 NAN。
最后说结论：float 型可以作为 key，但是由于精度的问题，会导致一些诡异的问题，慎用之。

### 一边遍历一边删除
线程不安全，慎用或者加锁
在查找、赋值、遍历、删除的过程中都会检测写标志，一旦发现写标志置位（等于1），则直接 panic。赋值和删除函数在检测完写标志是复位之后，先将写标志位置位，才会进行之后的操作。
### Map判断相等
深度相等的条件：
1. 都为nil
2. 非空、长度相等，指向同一个map实体对象
3. 相应的key指向的value深度相等

nil只能用map==nil来，map1==map2是非法的。
所以最后要判断map相等，也只能遍历双方来进一步深度比较value了。
